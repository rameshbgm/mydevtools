# v1.5 follow-up — Honest AI tools, pipeline adoption, and cleanup

v1.5 shipped four foundations (pipelines, share URLs, PWA, extension) but adoption stalled at 7/107 tools, and a deeper audit found real defects undercutting the site's privacy-first pitch. This follow-up pass fixes those defects and grows the AI category — with one hard constraint on everything new: **no key, no server round-trip, no persistence.**

Note: the app-displayed version number (`APP_VERSION`) stays at `1.4` until this branch merges to `main` — this doc describes work that ships as part of the v1.5 changelog entry once merged, not a separate v1.6 release.

## Foundation hygiene

- **Deleted ~2,500 lines of dead code** — 105 of 116 tool pages were `"use client"` components that also exported `generateMetadata()`, which Next.js never calls on a client component. The real metadata always came from each tool's `layout.tsx`; these blocks were pure rot, hardcoding a stale `devtools-hub.com` domain. `scripts/remove-page-metadata.js` (already existed, fixed for CRLF files) did the removal.
- **`src/lib/download.ts`** — promoted `downloadBytes` out of `cert-utils.ts`, added a `downloadText` sibling, migrated 18 pages off inline `createObjectURL` boilerplate.
- **34 pages migrated to shared `copyToClipboard`** — they were calling `navigator.clipboard.writeText` directly, which has no fallback for non-secure contexts. The shared helper in `src/lib/clipboard.ts` already had an `execCommand` fallback; these pages just weren't using it.
- **`scripts/check-parity.js`** — new, runs on `prebuild`. Catches the class of drift bug that let `code-explainer`/`rag-search`/`text-summarizer` ship unreachable: registry ↔ url-table ↔ SEO coverage, orphan tool directories, dead `generateMetadata`, stale domain references, and `BRIDGE_TARGETS` rows that point at tools which don't actually consume the bridge.

## Orphan AI tools resolved

Three AI-category pages existed with SEO content and a `layout.tsx` but were never added to `tools-registry.ts` — unreachable from navigation or search since they were written.

- **Deleted** `code-explainer` (regex → canned-string chain) and `text-summarizer` (word-frequency extraction with a fake `setTimeout` delay simulating "processing"). Both presented heuristics as AI.
- **Rebuilt** `rag-search` → **Semantic Search Playground**, the one substantial rewrite in this release (see below).

## Cross-cutting UX (zero or near-zero per-page cost)

- **Related tools** — `ToolPageLayout` now renders up to 6 same-category tools ranked by shared tags, computed from the existing registry. No new registry field, no per-page changes.
- **On-page FAQ** — `ToolPageLayout` reads `SEO_CONTENT[toolId].faq` (previously only emitted as JSON-LD, never rendered) and shows it as a Collapse above the hydration-guard boundary. Renderer is centralized; FAQ *content* still only exists on ~15% of tools — writing the rest is ongoing background work, not blocked on this release.
- **Keyboard shortcuts** — `?` (outside inputs) opens a shortcuts help modal, extending the existing `AppShell.tsx` `⌘K` listener rather than introducing a new system.
- **Accessibility** — 95 icon-only buttons across 31 tool pages gained `aria-label`s (Copy, Clear, Download, Delete, and 10 other icon types). Previously only 2 of 116 tool pages had any `aria-*` attribute at all.

## Pipeline adoption — including a live bug fix

`BRIDGE_TARGETS` in `src/lib/tool-bridge.ts` declared 24 destinations for "Send to →", but only 7 tool pages actually read the bridge. The other 17 appeared in every SendTo dropdown and **silently dropped the payload** on arrival — a real, user-facing bug, not just missing adoption.

- Wired: `json-validator`, `json-to-csv`, `json-to-xml`, `json-to-typescript`, `json-diff`, `yaml-json-converter`, `xml-formatter`, `xml-to-json`, `xml-diff`, `text-diff`, `hmac-generator`, `regex-tester`, `case-converter`, `html-entities`, `html-formatter`, `markdown-preview`, `csv-to-json`, `csv-diff` — all 17.
- Diff tools (`json-diff`, `xml-diff`, `text-diff`, `csv-diff`) accept into their **left** pane only and don't emit — a diff's output is a visual comparison, not a forwardable payload.
- `toon-converter` got a full rebuild rather than a simple wire-up (below).
- Adoption: 7 → ~30 tools. Not chasing 107 — the bridge is meaningless for `coin-toss` or `qr-generator`.

## TOON Converter: real round-trip

The existing `toon-converter` was encode-only (JSON/XML → TOON, no decoder), wasn't bridge-wired, and advertised "token savings" while measuring only **character** count.

- **Added `decodeToon`** — the actual inverse of `encodeToon`, extracted alongside it into `src/lib/toon.ts` for reuse and testability. Handles tabular arrays, nested objects, nested lists, quoted strings, and the bare-empty/quoted-empty distinction TOON uses to preserve `null` through tabular cells.
- **Direction toggle** — JSON/XML → TOON and TOON → JSON/XML, both directions.
- **Real token counts** via `gpt-tokenizer`, replacing the `chars / 4` approximation.
- **`scripts/toon-roundtrip.test.ts`** — 20 fixtures asserting `decodeToon(encodeToon(x))` deep-equals `x`, covering tabular arrays, nested lists, unicode, quoting edge cases, and the null/empty-string cell ambiguity. Run via `npm run test:toon` (added `tsx` as a devDependency to run it).

## New AI tools — all local, all key-free

Selection filter for everything below: **must work with no API key, no signup, no server, no persisted state.** This ruled out the most obvious AI feature — a BYOK prompt playground — since a user's API key in `localStorage`, or transiting the server via `/api/proxy-stream`, both fail the constraint outright. Not deferred; rejected.

- **LLM Token Counter** (`token-counter`) — `gpt-tokenizer` for exact GPT/o200k_base and cl100k_base counts (pure JS, inline BPE tables, no WASM, no network); Claude/Llama get a labeled `~3.5 chars/token` estimate, never presented as exact. Context-budget bar with system-prompt and history token inputs.
- **Fine-Tuning Dataset Validator** (`jsonl-validator`) — per-line JSON + schema validation against OpenAI's `messages` format or Anthropic's `system` + `messages` format (role ordering, alternation, required fields), with per-line token counts. Files are read via the browser File API and never uploaded — the whole point, given people are understandably nervous about training-data exfiltration.
- **Agent Card / MCP Manifest Generator** (`agent-manifest-generator`) — form-driven `agent-card.json` (A2A) and MCP `mcpServers` client-config builder, with live validation and a `SendToButton` straight into the existing `a2a-inspector` / `mcp-inspector`. Both inspectors gained a `ToolBridgeBanner` to receive it — `a2a-inspector` loads the card directly (skipping the fetch), `mcp-inspector` maps the first `mcpServers` entry into its connection form.
- **Model & Pricing Comparison** (`model-pricing-reference`) — static comparison table (context window, max output, per-Mtok pricing, cached-input discount, vision/tools support) across Anthropic/OpenAI/Google/Meta/Mistral, cloning the existing `rfc-standards` table pattern. Filed under **Reference**, not AI — it's a lookup table. Carries a visible `LAST_VERIFIED` date and per-row links to each provider's own pricing page, since LLM pricing goes stale fast.
- **Semantic Search Playground** (`rag-search`, rebuilt) — real embeddings via `@huggingface/transformers` (`onnx-community/all-MiniLM-L6-v2-ONNX`, 384-dim), WebGPU with automatic WASM fallback if WebGPU init fails. Cosine similarity ranks chunks against a query — genuinely finds semantically related text the old substring-matching version couldn't. The one privacy nuance in this release: ~25 MB of model weights download from the Hugging Face CDN on first use. That's disclosed on-page, gated behind an explicit "Load model" button (never automatic), and user text never leaves the browser — only the model comes in.

**Rejected for this release:** a BYOK prompt playground (fails the key-free constraint outright, see above), a Jinja chat-template renderer (niche audience, lowest expected use), a standalone system-prompt inspector (the token counter's budget bar already covers the real need).

## Privacy claim accuracy

`SITE_TAGLINE` said `"Free Online Developer Tools: 100% Client-Side"` — false for the 8 tools that do hit a server route (`api-request-builder`, `a2a-inspector`, `mcp-inspector`, `soap-client`, `wsdl-parser`, `certificate-inspector`, `certificate-chain-validator`, `webhook-receiver`). Per-tool disclosure via `ServerProxyNotice` was already accurate and specific; only the site-level superlative overreached.

Changed to `"Free Online Developer Tools — Client-Side by Default"`, and the footer's `"100% client-side · no data leaves your browser"` to `"Client-side by default · see each tool for details"`. This reads as more trustworthy, not less — a site that documents its one exception beats a blanket claim that one counterexample discredits.

## What's next

- **FAQ content backfill** — the renderer is done; only ~15% of tools have `faq` entries written. Prioritize formatters and validators (highest traffic) 10-15 tools per sitting.
- **Sample/"Load example" data** — 84 tools still lack it. No central mechanism exists (each tool's input setter is different), so this is a long tail of small per-page additions, not blocked on anything.
- **framer-motion removal from the shared bundle** — it's already in `AppShell`/`ToolPageLayout` in the root layout, so lazy-loading it on individual pages saves nothing. The real fix (replacing the shell's motion usage with CSS transitions) is a dedicated pass, not a quick win.
- **Bridge adoption ceiling** — ~30/107 tools is likely close to the honest ceiling; most remaining tools (games, generators, reference lookups) have no meaningful payload to send or receive.
