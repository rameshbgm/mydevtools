# v1.4 — Four new directions, 14 new tools

v1.4 ships **14 new tools, all fully functional**, plus one new category (**Image & Media**) and two new API routes for in-memory webhook capture.

## Scope at a glance

| Direction | Category | New tools |
|-----------|----------|-----------|
| **A. Networking & Web** | `Network` (existing) | Webhook Receiver, WebSocket Tester, CORS Tester, DNS Lookup |
| **B. Diff & Compare** | `Diff & Compare` (existing) | Image Diff, CSV Diff |

## Tool reference

### A. Networking & Web

**`webhook-receiver` — `/network/webhook-receiver`**

Generates a stable session ID (stored in localStorage), exposes a public URL `/api/webhook/<sessionId>`, and long-polls `/api/webhook/<sessionId>/events` for new requests. Captured request data: method, path, query, headers, body (UTF-8 or base64). Session retained 1 hour idle, max 200 requests, FIFO eviction. Backed by `src/lib/webhook-store.ts` (process-local; evaporates on redeploy).

**`websocket-tester` — `/network/websocket-tester`**

Pure-browser WebSocket client using the global `WebSocket` constructor. Three frame directions: `sent` (▲), `received` (▼), `system` (•). Binary frames are reported as `[binary, N bytes]`.

**`cors-tester` — `/network/cors-tester`**

Sends a real `fetch()` from this origin, classifies failures into:
- **Preflight failure** — triggered by non-simple method, custom headers, or non-simple `Content-Type`. Tool tells you which one.
- **Simple-request failure** — upstream returned no `Access-Control-Allow-Origin` matching this origin.
- **HTTP error** — CORS was fine; upstream returned 4xx/5xx.

**`dns-lookup` — `/network/dns-lookup`**

Parallel fan-out across selected record types via DNS-over-HTTPS (Cloudflare 1.1.1.1 or Google 8.8.8.8). Supports A, AAAA, CNAME, MX, TXT, NS, SOA, CAA, SRV. Copy as zone-file lines.

### B. Diff & Compare

**`csv-diff` — `/diff-and-compare/csv-diff`**

RFC 4180-inspired CSV parser (handles quoted fields with embedded commas/newlines/escaped quotes). Key-column row matching, column-level change highlighting, four row statuses (added/removed/modified/unchanged), copyable audit report.

**`image-diff` — `/diff-and-compare/image-diff`**

Loads two images into Canvas, three comparison modes:
- **Side-by-side** — two images with a 4px separator.
- **Overlay** — composite with adjustable top-image opacity.
- **Difference** — pixel-by-pixel comparison; changed pixels colored red over a desaturated base. Adjustable tolerance (0–64); diff-pixel count and percentage shown.

### C. Image & Media (new category)

**`image-compressor` — `/image-and-media/image-compressor`**

Canvas `toBlob(format, quality)` re-encode with JPEG/WebP/PNG output and optional max-dimension resize. Live before/after preview and byte savings. PNG quality is fixed by spec (input gets disabled).

**`svg-optimizer` — `/image-and-media/svg-optimizer`**

Pure-regex pass over SVG markup. Six toggleable transforms (strip comments, XML declaration, editor metadata, empty attributes, collapse whitespace, round numeric precision). Decimal precision 0–6 via slider. Side-by-side rendered preview with checkerboard background.

**`favicon-generator` — `/image-and-media/favicon-generator`**

High-quality canvas downscale to 7 standard sizes. Non-square sources are letterboxed centred. Outputs PNG per size, plus copy-paste-ready HTML `<head>` snippet and a PWA `site.webmanifest`.

**`color-palette-extractor` — `/image-and-media/color-palette-extractor`**

Downsamples to ≤200px on the longest side, runs 8-iteration k-means in RGB space, sorts swatches by cluster size. Outputs HEX, RGB, HSL plus % of pixels per swatch. Configurable palette size 3–16. Skips near-transparent pixels.

**`exif-viewer` — `/image-and-media/exif-viewer`**

In-file EXIF parser (~150 lines). Reads APP1 segment from JPEG, walks the TIFF IFD, decodes ASCII/short/long/rational types. Groups tags into Camera/Lens/Capture/Image/GPS. Converts GPS rational triplets into decimal lat/lon with an OpenStreetMap link.

### D. Data Conversion

**`mock-data-generator` — `/data-converters/mock-data-generator`**

15 field types. Mulberry32 RNG (seedable for byte-identical CI fixtures). Outputs JSON, CSV, or PostgreSQL-flavoured SQL inserts.

**`toml-converter` — `/data-converters/toml-converter`**

Minimal in-file TOML parser (sections, dotted keys, scalars, arrays of scalars). YAML support via the existing `yaml` dependency. Bidirectional any-to-any conversion. Edge cases (inline tables, arrays of tables) intentionally unsupported — convert via JSON for those.

**`toon-converter` — `/data-converters/toon-converter`**

JSON or XML → TOON (Token-Oriented Object Notation). XML parses via the browser's `DOMParser`; attributes become `@attr` keys, sibling elements with the same tag collapse into arrays. The encoder detects **uniform tabular arrays** (array of objects, same scalar fields) and emits a single `key[N]{f1,f2}:` header plus CSV-style rows — the main compression win. Live badges: input chars, output chars, characters saved (and a rough `≈ tokens saved` estimate at ~4 chars/token for LLM budgeting).

## New infrastructure

### `src/app/api/webhook/[sessionId]/route.ts`

Catch-all endpoint accepting GET/POST/PUT/PATCH/DELETE/OPTIONS/HEAD. Validates session id format (`^[A-Za-z0-9_-]{6,64}$`). Captures method, path, query, headers, and body (UTF-8 with base64 fallback for binary). Returns `{ ok: true, id }` so upstream test harnesses see HTTP 200.

### `src/app/api/webhook/[sessionId]/events/route.ts`

Long-poll endpoint. `GET ?since=N&wait=ms` returns captured requests with `id > N`; holds the connection up to `wait` ms (clamped to 25s) waiting for new requests. `DELETE` clears the session history.

### `src/lib/webhook-store.ts`

Process-local in-memory store, attached to `globalThis` so it survives Next.js hot reload in dev. GC pass runs on every read; sessions idle > 1h are dropped. Each session capped at 200 requests with FIFO eviction.

### `src/components/ServerProxyNotice.tsx`

`ServerRouteId` extended with `proxy-stream` and `webhook`. New entries added to `ROUTE_FILE` so the GitHub source link works for both.

## Risk and rollback

- **Zero new dependencies.** Every tool reuses existing imports; YAML/TOML conversion uses the existing `yaml` package plus an in-file TOML parser.
- **One new API surface area.** `/api/webhook/[sessionId]` is server-side state-keeping; the rest is client-only.
- **No breaking changes** to existing routes, registry types or store shape. Adding a new union member to `ToolCategory` and `ServerRouteId` is additive.
- **Rollback** = `git revert` of the v1.4 commit. The new category becomes invisible because no tool references it; everything else is additive.

## What's next (post-v1.4)

- Promote `webhook-receiver` from in-memory to Redis/KV when traffic justifies it.
- Add **multi-image batch** mode to Image Compressor and Favicon Generator.
- Add **arrays-of-tables** support to the TOML parser (the one common case currently unsupported).
- Consider extracting the EXIF parser into `src/lib/exif.ts` once a second tool needs it.
